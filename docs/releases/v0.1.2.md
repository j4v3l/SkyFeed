# SkyFeed 0.1.2 preview

This preview makes SkyFeed friendlier for everyday local use while strengthening
its multi-feeder runtime. Administrators can give local and invited feeders
approved public names, retain those names across restarts, and select a named
feeder as the server's default view.

Display preferences now offer three consistent systems. Imperial is the new
server fallback, alongside Aviation and Metric, while saved personal Aviation
or Metric preferences remain unchanged. Aircraft, weather, activity, tracks,
alerts, dashboards, reports, flight leaders, and audits share the same unit
formatting rules.

The release also adds audited message deletion, a persistent live flight-leader
card, and measured multi-feeder allocation and contention improvements. Live
snapshots remain immutable, queues and tracking remain bounded, and enrichment
stays outside the ingest hot path.

## Upgrade

Back up SQLite before upgrading. Migration 015 preserves explicit member unit
preferences and changes every server default to Imperial.

```sh
SKYFEED_IMAGE=ghcr.io/j4v3l/skyfeed:0.1.2 \
  docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.local.yaml up -d
```

Use the immutable image digest recorded on the GitHub Release for production.
Images are published for Linux AMD64 and ARM64 with an SBOM, provenance
attestation, vulnerability scan, and keyless signature.

## Preview notes

- Movement labels remain inferred trends rather than official airport events.
- Community ingress remains disabled until an administrator configures its
  private HTTPS path and creates an invitation.
- The 24-hour target-host soak remains a v1.0 gate.
